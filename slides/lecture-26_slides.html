Closure Tricks

What’s closure?

  • Complement: make the DFA total (add SINK if needed), then flip accept to non-accept, and vice-versa.
  • Union / Intersection: States are pairs (p,q)
    • Union accepts if p ∈ F1 or q ∈ F2
    • Intersection accepts if p ∈ F1 and q ∈ F2
  • Difference: L1 - L2 = \(L1\cap L2^c\)

This mirrors set algebra directly; great place to reinforce recent set lessons.

Closure answers “What’s closure?”: if we start with regular languages and take a complement, union, intersection or difference, the result is regular again. We never leave the family. Same word as “the integers are closed under +”.

Why total: a DFA that is missing an arrow rejects by “falling off”. Flipping the double circles doesn’t flip falling off, so the missing-arrow strings would be rejected by both machines. Add a SINK state first (Starts with Iced from Friday had one), then flip; SINK becomes accepting.

Two Machines at Once

Goal: one DFA for strings with an even number of 1s and ending in 1.

Machine D 🐙: even number of 1s

Warm-up: ends in 1

Feed the same string to both, one symbol at a time. What does the combined machine need to remember after each symbol?

Answer: where each machine is. That’s a pair of states, like (E, A): D is in E, the warm-up is in A. Run 0101 through each one separately first: D: E, E, O, O, E (accepts). Warm-up: A, A, B, A, B (accepts). Both accept, so 0101 is in the intersection. The pairs are just these two rows read top to bottom together: (E,A) (E,A) (O,B) (O,A) (E,B).

Build It: One Row per Pair

D 🐙: even number of 1s

Warm-up: ends in 1

A state is a pair: (D’s state, warm-up’s state).

On a symbol, each machine takes its own step.

pair on 0 on 1 D accepts? warm-up accepts?
(E,A) start (E,A) (O,B) yes no
(E,B)        
(O,A)        
(O,B)        

Filled table: (E,A): 0 → (E,A), 1 → (O,B); D yes, warm-up no (E,B): 0 → (E,A), 1 → (O,B); D yes, warm-up yes (O,A): 0 → (O,A), 1 → (E,B); D no, warm-up no (O,B): 0 → (O,A), 1 → (E,B); D no, warm-up yes Intersection (and) accepts where both are yes: only (E,B). Union (or) accepts where either is yes: (E,A), (E,B), (O,B). With bigger machines not every pair can be reached from the start. Build rows only for pairs that show up in the table (the Exercise at the end has 9 pairs, 7 reachable).

Non-deterministic FA

NFAs

DFA: exactly one transition for each input symbol in each state. NFA: may have multiple choices on a symbol and \(\varepsilon\)-moves (move without consuming input).

Acceptance: a string is accepted if there exists a path that reads all characters and lands in an accept state.

Just showing they exist. This NFA accepts the strings that end in 00: from P on a 0 it may stay or move to Q, and a path that needs a missing arrow dies. Compare Machine B 🐢, the DFA for the same language. Every NFA has a DFA that accepts the same strings, so NFAs recognize nothing new.

Watch It Run

Same NFA: ends in 00. Step through a string and watch every state it could be in light up.

Try 0100, then 1001.

0100: {P} → {P,Q} → {P} → {P,Q} → {P,Q,R}. R is live at the end: accept. 1001: {P} → {P} → {P,Q} → {P,Q,R} → {P}. Reject. A path that needs a missing arrow just dies: after 01, the path that went to Q on the 0 has nowhere to go on the 1. Live states are the whole idea; the lit-up set is all the computer has to remember.

Notes on NFAs

  • Direct from a regex: Translate patterns piece-by-piece without tricky state discovery.

  • Local “gadgets”: Build tiny NFAs for literal, union (\(|\)), concatenation, Kleene star (\(^*\)) and wire together with \(\varepsilon\).

  • NFAs and DFAs have the same power!! (Kleene’s Theorem)

  • Build a DFA from NFA algorithmically if you need one.

Message: “We model the branching in the regex directly; acceptance means at least one successful path.”
